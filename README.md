# دوز هوشمند (Smart Tic Tac Toe / Three Men's Morris)

بازی خانه سه‌در‌سه با دو فاز: چیدن مهره و جابه‌جایی مهره، به‌همراه هوش مصنوعی، تایمر ۳۰ ثانیه‌ای،
پشتیبانی دوزبانه (فارسی/انگلیسی) و امتیازدهی.

## چه چیزی همین الان کار می‌کند؟ (بدون نیاز به هیچ سرویس بیرونی)

- ✅ منطق کامل بازی: فاز چیدن + فاز جابه‌جایی
- ✅ قانون منع بازگشت مهره به خانه‌ی مرحله‌ی قبل (با پیام خطا)
- ✅ تشخیص برد در تمام خطوط افقی/عمودی/مورب
- ✅ تایمر ۳۰ ثانیه‌ای؛ در صورت اتمام زمان، حرکت به‌صورت خودکار انجام می‌شود
- ✅ حالت تک‌نفره مقابل هوش مصنوعی (اکتشافی: برد فوری > بلاک حریف > مرکز > تصادفی)
- ✅ حالت دو نفره روی یک گوشی (Pass and Play)
- ✅ رابط کاربری دوزبانه فارسی/انگلیسی با یک دکمه
- ✅ ذخیره‌ی محلی امتیاز و نام بازیکن (SharedPreferences)
- ✅ **ساخت خودکار فایل APK با GitHub Actions** (بدون نیاز به نصب Flutter روی سیستم شما!)

## 🚀 ساده‌ترین راه گرفتن APK: GitHub Actions (پیشنهاد می‌شود)

با این روش، خود گیت‌هاب فایل APK را برایتان می‌سازد — نیازی به نصب Flutter روی گوشی یا
کامپیوترتان نیست.

1. یک حساب رایگان در [github.com](https://github.com) بسازید (اگر ندارید).
2. یک ریپازیتوری (Repository) جدید بسازید — می‌تواند **Private** یا **Public** باشد.
3. محتوای همین پوشه‌ی `tic3` (تمام فایل‌ها، از جمله پوشه‌ی مخفی `.github`) را در آن ریپازیتوری
   آپلود کنید. ساده‌ترین راه: در صفحه‌ی ریپازیتوری روی «Add file → Upload files» بزنید و
   تمام فایل‌های داخل `tic3` را بکشید و رها کنید (drag & drop)، سپس «Commit changes».
   - نکته: پوشه‌ی `.github` مخفی است؛ مطمئن شوید هنگام آپلود آن را هم اضافه کرده‌اید (اگر از
     Git خط‌فرمان استفاده می‌کنید این پوشه خودکار اضافه می‌شود: `git add .`).
4. به تب **Actions** در بالای صفحه‌ی ریپازیتوری بروید. یک workflow به‌نام «Build APK» را
   می‌بینید که خودش شروع به اجرا می‌شود (چون فایل‌ها را push کردید).
5. صبر کنید (حدود ۳ تا ۵ دقیقه) تا اجرا با علامت ✅ سبز تمام شود.
6. روی همان اجرا (run) کلیک کنید؛ در پایین صفحه بخش **Artifacts** را ببینید —
   فایل `tic3-smart-apk` را دانلود کنید. این یک فایل زیپ حاوی `app-release.apk` است.
7. فایل APK را از حالت زیپ خارج کنید، به گوشی اندرویدتان بفرستید و لمسش کنید تا نصب شود
   (ممکن است لازم باشد گزینه‌ی «نصب از منابع ناشناس» را در گوشی فعال کنید).

بعد از این مرحله، هر بار که کد را تغییر دهید و دوباره push کنید، یک APK جدید خودکار ساخته می‌شود.



- ⏳ بازی آنلاین (اتاق بازی + همگام‌سازی حرکت‌ها) → نیاز به پروژه‌ی Firebase شخصی شما
- ⏳ بازی با افراد نزدیک (بلوتوث/وای‌فای مستقیم) → نیاز به پکیج nearby_connections
- ⏳ تولید و اسکن QR کد برای ساخت/پیوستن به اتاق → نیاز به qr_flutter و mobile_scanner
- ⏳ رتبه‌بندی کشوری/جهانی → نیاز به یک دیتابیس آنلاین (Firestore پیشنهاد می‌شود)
- ⏳ پایان‌دادن به بازی هنگام قطع اتصال حریف → منطق آن باید روی Firestore پیاده شود (پایین توضیح داده شده)

این‌ها را عمداً به‌صورت جدا نگه داشتم چون هرکدام نیاز به یک حساب/پروژه‌ی Firebase با کلید API
مخصوص *شما* دارند که من نمی‌توانم از طرف شما بسازم؛ ولی معماری پروژه طوری چیده شده که افزودنشان ساده باشد.

## ۱) نصب و اجرا روی سیستم خودتان (مرحله به مرحله)

### پیش‌نیاز: نصب فلاتر
1. از سایت رسمی، Flutter SDK را دانلود کنید: https://docs.flutter.dev/get-started/install
2. دستور زیر را بزنید تا مطمئن شوید درست نصب شده:
   ```
   flutter doctor
   ```
   هر موردی که ❌ نشان داد را طبق راهنمایی خودش رفع کنید (مثلاً نصب Android Studio برای اندروید).

### اجرای پروژه
1. پوشه‌ی `tic3` (همین پروژه) را از حالت فشرده خارج کنید.
2. داخل پوشه بروید و پکیج‌ها را نصب کنید:
   ```
   cd tic3
   flutter pub get
   ```
3. گوشی اندروید را با کابل USB وصل کنید و **حالت توسعه‌دهنده (Developer Options)** و
   **USB Debugging** را در گوشی فعال کنید. یا یک شبیه‌ساز (Emulator) باز کنید.
4. اجرا کنید:
   ```
   flutter run
   ```
   بازی مستقیم روی گوشی/شبیه‌سازتان نصب و اجرا می‌شود.

### ساخت فایل نصبی APK (برای نصب دستی روی هر گوشی اندرویدی)
```
flutter build apk --release
```
فایل خروجی اینجا ساخته می‌شود:
```
build/app/outputs/flutter-apk/app-release.apk
```
این فایل را برای گوشی بفرستید (تلگرام، بلوتوث، کابل) و روی گوشی لمسش کنید تا نصب شود
(ممکن است لازم باشد گزینه‌ی «نصب از منابع ناشناس» را در گوشی فعال کنید).

### برای iOS
ساخت IPA نیاز به مک و Xcode دارد:
```
flutter build ios --release
```
سپس از طریق Xcode روی گوشی نصب یا برای TestFlight ارسال می‌شود.

## ۲) افزودن حالت آنلاین (Firebase) — گام‌به‌گام

1. به [console.firebase.google.com](https://console.firebase.google.com) بروید و یک پروژه‌ی جدید بسازید.
2. ابزار FlutterFire CLI را نصب کنید:
   ```
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
   این دستور خودش فایل `firebase_options.dart` را می‌سازد و اپ اندروید/iOS را به پروژه‌ی
   Firebase شما متصل می‌کند.
3. در `pubspec.yaml` خطوط مربوط به `firebase_core` و `cloud_firestore` را از حالت کامنت خارج کنید
   و دوباره `flutter pub get` بزنید.
4. یک ساختار Firestore پیشنهادی برای اتاق بازی:
   ```
   rooms/{roomId}
     board: [null,null,...]   // 9 خانه
     phase: "placement" | "movement"
     currentPlayer: 0 | 1
     players: { "0": {uid, name, lastSeen}, "1": {...} }
     winner: null | 0 | 1
     createdAt: timestamp
   ```
5. منطق پیشنهادی: هر حرکت به‌جای فراخوانی مستقیم `GameEngine`، سند Firestore را با
   `runTransaction` آپدیت می‌کند و هر دو گوشی با `snapshots()` تغییرات را لحظه‌ای دریافت می‌کنند.
   فایل `logic/game_engine.dart` (که همین الان ساختمش) کاملاً مستقل از UI است، پس همان منطق
   اعتبارسنجی حرکت را می‌توانید عیناً روی داده‌ی دریافتی از Firestore هم اجرا کنید.
6. **قطع اتصال بازیکن:** هر گوشی هر ۵ ثانیه فیلد `lastSeen` خودش را آپدیت کند. اگر گوشی
   مقابل بیش از مثلاً ۲۰ ثانیه آپدیت نشد، سمت دیگر برنده اعلام می‌شود (این چک را می‌توان
   سمت کلاینت یا با Cloud Function انجام داد).

## ۳) افزودن QR کد برای ساخت/پیوستن به اتاق

1. پکیج‌های `qr_flutter` (تولید) و `mobile_scanner` (اسکن) را از کامنت خارج کنید.
2. بازیکن اول یک `roomId` تصادفی (مثلاً UUID) می‌سازد، سند اتاق را در Firestore ایجاد می‌کند و
   با `QrImageView(data: roomId)` آن را روی صفحه نشان می‌دهد.
3. بازیکن دوم با `MobileScanner` کد را اسکن می‌کند، `roomId` را می‌خواند و به همان سند Firestore
   می‌پیوندد (`players["1"]` را با اطلاعات خودش پر می‌کند).

## ۴) افزودن بازی نزدیک (بلوتوث / وای‌فای مستقیم، بدون اینترنت)

1. پکیج `nearby_connections` را از کامنت خارج کنید (بر پایه‌ی Google Nearby Connections API است
   و خودش تصمیم می‌گیرد از بلوتوث یا وای‌فای مستقیم استفاده کند).
2. یک گوشی با `Nearby().startAdvertising(...)` قابل‌کشف می‌شود، گوشی دیگر با
   `Nearby().startDiscovery(...)` آن را پیدا می‌کند.
3. بعد از برقراری اتصال (`Nearby().sendPayload(...)`)، همان JSON وضعیت بازی (board, phase,
   currentPlayer) بین دو گوشی رد و بدل می‌شود — دقیقاً همان الگوی حالت آنلاین، فقط به‌جای
   Firestore از پیام مستقیم بین دستگاه‌ها استفاده می‌شود.

## ۵) رتبه‌بندی کشوری/جهانی

بعد از هر بازی، رکورد برد/باخت را در یک کالکشن Firestore به‌نام `leaderboard` ذخیره کنید:
```
leaderboard/{uid}
  name, country, wins, totalGames, score
```
برای رتبه‌ی جهانی: `orderBy('score', descending: true)`
برای رتبه‌ی کشوری: همان کوئری + `where('country', isEqualTo: myCountry)`

## ۶) ساخت خودکار APK با GitHub Actions (پیشنهادی — بدون نصب هیچ‌چیزی روی سیستم خودتان)

این پروژه از قبل شامل فایل `.github/workflows/build-apk.yml` است که به‌صورت خودکار APK می‌سازد.
مراحل استفاده:

1. یک حساب رایگان در [github.com](https://github.com) بسازید (اگر ندارید).
2. یک ریپازیتوری (repository) جدید و **خصوصی یا عمومی** بسازید، مثلاً به‌نام `tic3-smart`.
3. کل پوشه‌ی این پروژه (همان چیزی که الان دارید، شامل پوشه‌ی `.github`) را در آن ریپازیتوری آپلود کنید:
   - ساده‌ترین راه: از داخل صفحه‌ی ریپازیتوری در گیت‌هاب، گزینه‌ی «Add file → Upload files» را
     بزنید و همه‌ی فایل‌ها/پوشه‌ها را بکشید و رها کنید، سپس Commit بزنید.
   - یا با خط فرمان:
     ```
     cd tic3
     git init
     git add .
     git commit -m "پروژه اولیه"
     git branch -M main
     git remote add origin https://github.com/USERNAME/tic3-smart.git
     git push -u origin main
     ```
4. به تب **Actions** در صفحه‌ی گیت‌هاب ریپازیتوری بروید. workflow به‌نام «Build APK» خودش
   شروع به اجرا می‌کند (چند دقیقه طول می‌کشد).
5. وقتی سبز شد (✅)، روی همان اجرا (run) کلیک کنید؛ پایین صفحه بخش **Artifacts** را ببینید و
   فایل `tic3-smart-apk` را دانلود کنید — همان فایل APK نهایی است که مستقیم روی گوشی نصب می‌شود.
6. از این به بعد، هر وقت کدی تغییر داد و دوباره push کردید، یک APK جدید خودش ساخته می‌شود —
   یا از همان تب Actions دکمه‌ی «Run workflow» را برای ساخت دستی بزنید.



```
lib/
  main.dart                  نقطه‌ی ورود برنامه
  localization/app_strings.dart   متن‌های فارسی/انگلیسی
  models/game_state.dart     مدل وضعیت بازی (تخته، مهره‌ها، فاز، امتیاز)
  logic/game_engine.dart     قوانین بازی، اعتبارسنجی حرکت، تشخیص برد، هوش مصنوعی
  screens/home_screen.dart   منوی اصلی
  screens/game_screen.dart   صفحه‌ی بازی + تایمر
  screens/profile_screen.dart
  screens/online_placeholder_screen.dart
  widgets/board_widget.dart  رسم صفحه‌ی ۳در۳
```

نکته: تمام منطق بازی (`game_engine.dart`) کاملاً از رابط کاربری جداست، پس همین فایل بدون تغییر
هم برای حالت آفلاین و هم برای اعتبارسنجی حرکت‌ها روی سرور/Firestore قابل استفاده است.
